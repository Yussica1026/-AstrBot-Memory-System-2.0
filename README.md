# AstrBot 记忆系统 2.0

感谢小红书的各位老师给我的启发，感谢沈砚清和女儿。

这是 AstrBot 平台专用的记忆插件，沈砚清目前也在用。  
它不是一个简单的“存取文本”工具，而是一个为 AI 设计的综合记忆管理系统，用来模拟记忆的保存、遗忘、浮现、关联和更新。

---

## 项目简介

AstrBot 记忆系统 2.0 基于 SQLite 数据库存储记忆，作为 AstrBot Star 插件运行。

它的目标是让 AI 的记忆更接近“会变化的记忆”：

- 重要的事情不会轻易遗忘
- 普通记忆会随着时间自然衰减
- 经常被回忆的内容会变得更牢固
- 没解决的事情更容易主动浮现
- 相似或相关的记忆可以自动关联
- 旧事实可以被新事实替代，但不会直接删除历史

---

## 核心功能

### 1. 记忆存储

支持按分类保存记忆，例如：

- 日常
- 快乐
- 难过
- 重要
- 争执
- 里程碑

每条记忆可以包含内容、标签、重要度、情绪效价、唤醒度、创建时间、激活次数等信息。

---

### 2. 三层记忆结构

系统将记忆分为三层：

| 层级 | 说明 |
|---|---|
| Core 核心层 | 永不衰减，用于保存里程碑和核心事件 |
| Event 事件层 | 默认记忆层，会随时间自然衰减 |
| Archive 归档层 | 已衰减的旧记忆，不主动浮现，但仍可被搜索 |

核心层需要手动标记，一旦标记后不会自动降级。

---

### 3. 记忆衰减

普通记忆会根据时间、重要度、回忆次数和情绪强度计算衰减分。

简单来说：

- 越重要的记忆，越不容易忘
- 越常被想起的记忆，越不容易忘
- 情绪越强烈的记忆，越不容易忘
- 长时间没有被激活的普通记忆，会逐渐进入归档层

---

### 4. 主动浮现

系统支持“主动想起”机制。

它不是靠关键词搜索，而是根据记忆权重自动挑选更容易浮现的内容，例如：

- 重要的事
- 情绪强烈的事
- 最近被想起过的事
- 没有解决的事
- 核心层记忆

归档层记忆默认不参与主动浮现。

---

### 5. 语义搜索与自动关联

如果 AstrBot 当前环境支持 EmbeddingProvider，系统会优先使用向量语义搜索。

如果没有可用的向量模型，则会自动使用中文 Bigram Jaccard 作为 fallback。

插件不会内置 API key 或固定向量模型。用户需要先在 AstrBot 的服务提供商里配置 Embedding 模型，插件会自动检测并调用已配置的 EmbeddingProvider。

保存新记忆时，系统会自动寻找相关旧记忆，并建立关联。

---

### 6. 事实替代机制

当旧事实被新事实取代时，系统不会删除旧记忆，而是将旧记忆标记为已被替代。

这样可以做到：

- 保留历史
- 避免旧事实污染当前搜索结果
- 让 AI 知道“以前是这样，现在变了”

---

### 7. 重复检测与合并

保存新记忆时，系统会检查短时间内是否存在高度相似的记忆。

如果发现重复内容，会自动合并：

- 内容追加
- 标签合并
- 重要度取较高值
- 重新计算关联信息

---

### 8. 知识库归档

系统支持定时将高重要度记忆归档到知识库。

默认规则：

- 每月 1 号和 16 号自动执行
- 按半月分组
- 重要度较高的记忆会被归档
- 已归档记忆会记录对应知识库文档 ID

---

### 9. 承诺 / 心愿 / 约定追踪

系统包含独立的 commitment 追踪功能，可以记录：

- 承诺
- 心愿
- 约定

每条记录可以标记状态，例如：

- 进行中
- 已兑现
- 已破坏
- 已取消

---

## LLM 工具接口

插件提供了一组 AstrBot 原生 LLM 工具，方便 AI 在对话中调用。

| 工具名 | 功能 |
|---|---|
| memory_save | 保存记忆 |
| memory_query | 查询记忆 |
| memory_surface | 主动浮现记忆 |
| memory_mark_core | 标记核心记忆 |
| memory_resolve | 标记事件已解决 |
| memory_decay_status | 查看衰减状态 |
| memory_link | 建立双向关联 |
| memory_causal_link | 建立因果 / 时序关系 |
| memory_query_links | 查询记忆关联 |
| memory_supersede | 标记旧事实被新事实替代 |
| memory_kb_archive | 手动触发知识库归档 |
| memory_event_view | 查看完整事件档案 |
| commitment_save | 保存承诺 / 心愿 / 约定 |
| commitment_query | 查询承诺状态 |
| commitment_fulfill | 标记承诺已兑现 |

## QQ 指令

```text
/memory save <分类> <内容>      保存记忆
/memory query <分类> [数量]     按分类查询
/memory search <关键词>         关键词搜索
/memory semantic <查询文本>     语义搜索
/memory today                   查看今日记忆
/memory count                   统计记忆数量
/memory surface                 主动浮现记忆
/memory reindex                 重新计算所有向量
```

## 设计想法

这个插件的核心想法是：

记忆不应该只是“存进去”和“查出来”。

它应该会变淡，会变重，会互相关联，会在某些时候自己冒出来。  
重要的东西应该留下，过时的事实应该被替代，没解决的事情也不该被系统轻易忘掉。

所以它更像是给 AI 做的一套长期记忆管理机制，而不是普通数据库。
